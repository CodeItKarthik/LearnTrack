# What is JDK, JRE, and JVM

---

## 1. JVM (Java Virtual Machine)
The **JVM** is the foundational engine that actually executes your Java program. It converts the compiled Java bytecode into machine-specific code that your computer's OS can understand.

* **Core Responsibility:** It executes Java bytecode (.class files) line by line.
* **Platform Independence:** Because the JVM translates bytecode into native instructions for your specific OS (Windows, macOS, Linux), it gives Java the "Write Once, Run Anywhere" (WORA) capability.
* **Memory Management:** It handles automatic memory allocation and garbage collection to keep the application running efficiently.
* **Relationship:** The JVM is embedded within both the JRE and the JDK.

## 2. JRE (Java Runtime Environment)
The **JRE** is the software package that provides the physical environment required to run Java programs. It bundles the JVM together with core Java class libraries (like `java.lang`, `java.util`, and `java.swing`) and supporting files.

* **Core Responsibility:** It is used primarily by end-users or systems that simply need to **run** Java applications.
* **Limitations:** It **does not** contain any development tools (like compilers or debuggers).
* **Relationship:** JRE = JVM + Core Java Class Libraries.

## 3. JDK (Java Development Kit)
The **JDK** is a comprehensive, full-featured software development kit. It includes everything present in the JRE, along with the development tools (like `javac`, `jar`, and debuggers) necessary to write, compile, test, and deploy Java programs.

* **Core Responsibility:** It is used by Java developers to **create** and **compile** Java code.
* **Compilation:** It contains `javac` (the Java compiler), which translates human-readable `.java` source code into platform-independent `.class` bytecode.
* **Relationship:** JDK = JRE + Development Tools.

## The Hierarchy (Summary)

To put it simply:
* **JVM** runs the bytecode.
* **JRE** provides the libraries needed to run the bytecode.
* **JDK** provides the tools required to write and compile the code into bytecode.

# What is bytecode
Java bytecode is the **intermediate**, **platform-independent** instruction set generated by the Java compiler (javac) when it compiles human-readable `.java` source code. Instead of being targeting to a specific computer's hardware CPU, bytecode is written for a virtual processor called the **Java Virtual Machine(JVM)**. It is saved inside compiled files with a `.class` extension.

---

# What does “write once, run anywhere” mean
In java **"Write Once, Run Anywhere" (WORA)** means that you can write and compile your code on one operating system (like windows) and run it on any other platform (like macOS or Linux) without modifying the code or recompilation. This core feature gives java its highly valued platform independence.

## How it works behind the scenes
Unlike traditional languages like C or C++, which compile directly into machine-specific code, Java uses an intermediate step:
1. **Write Source Code:** You write human-readable code in a `.java` file.
2. **Compile to Bytecode:** The Java compiler(javac) converts your source code into a platform-neutral intermediate format called **bytecode** (stored in a `.class` file).
3. **Execute via JVM:** The **Java Virtual Machine(JVM)** on the target machine reads this bytecode and translates it into native machine instructions on the fly.
